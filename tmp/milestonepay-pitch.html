Sponsor integration

Arkiv is the backbone
of MilestonePay's protocol memory

01

Avalanche events → Arkiv

The API indexer reads Fuji escrow events from block 58,333,416 and writes idempotent canonical entities: protocol_event, deal, settlement, dispute.

→
02

Evidence descriptors

After the provider submits delivery to Swarm ACT, the public descriptor is verified against the on-chain commitment and stored as an evidence entity in Arkiv.

→
03

Agreement identities

Participants bind their Swarm public key to their on-chain role. These agreement_identity entities gate dispute evidence access — arbiter must be committed before dispute evidence is sealed.

→
04

Reputation inputs

The reputation engine reads settlement and deal entities from Arkiv to compute deterministic, explainable scores per wallet. No off-chain DB needed.

Why Arkiv over a Web2 DB? Protocol history must survive the operator. Arkiv provides a permissioned, trusted-writer model where the indexer address is the only source of truth — not a mutable Postgres table the team could edit.

hashEvidenceDescriptor()
Decommission (M01)
ACT history references are immutable snapshots. Dispute evidence seals a specific ACT version — even if grantees are later revoked, the arbitration record persists.
Built to expire (M02)
Swarm private keys live only in the browser. No server ever sees ACT secrets. Evidence access expires naturally when grantees are revoked post-dispute.
Live wire (M03)
The evidence descriptor is live: grantees can be added dynamically via actAddGrantees() when the arbiter identity is committed, enabling real-time arbitration access.
